# EcoTwin permanent website plan

## Approved product scope and constraints
Make the existing EcoTwin City Traffic project a permanent public website. Preserve the uploaded SUMO network/routes and existing trained PPO policy; operate the PPO-controlled simulation in a persistent FastAPI/TraCI backend; stream live state to the React dashboard; expose viewing only (no public pause, single-step, or controller-mode controls); and publish the existing baseline-versus-PPO evaluation report. The user explicitly authorized WebDev Reserved Hosting and a public read-only deployment after its usage-based cost and resource limit were disclosed.

## Implementation approach
The canonical project serves a static React/Vite build and routes API, WebSocket, and health paths to a persistent Python container. The frontend uses same-origin relative API and WebSocket URLs. The backend uses the existing Gymnasium environment and SUMO network and keeps all TraCI calls on its dedicated single worker thread. Production runs the saved PPO actor deterministically. To keep the serving image small, export its linear/tanh actor parameters from the Stable-Baselines3 policy into an NPZ asset and implement equivalent NumPy-only actor inference in the container; keep PyTorch and Stable-Baselines3 for reproducible training/evaluation, not serving. SUMO and its matching tools are installed in the image, with `SUMO_HOME` and `SUMO_BINARY` set explicitly. Production mutation endpoints return forbidden and dashboard controls are omitted from the production build, while local development may retain controls.

WebDev publishes `frontend/dist` as static output and the Python service from a custom root Dockerfile. Route `/api/*`, `/ws/*`, and `/_app/health` to the server before the `/*` SPA/static rule. The container honors `PORT` and returns unauthenticated success at `/_app/health`. Declare the container and static build contracts, save the user's requested `always_on` residency using the platform's hosting confirmation Widget, checkpoint the intended changes on canonical `main`, and publish. Confirm both publication success and observed residency from `infra/overview`; a saved setting by itself is not proof that Reserved Hosting is live.

The 512 MiB plan limit is tight: prior local serving RSS was approximately 409 MiB for Python with PyTorch plus about 30 MiB for SUMO. Removing PyTorch from serving is intended to reduce that footprint. If the managed runtime, SUMO package install, or actual deployment fails its resource or policy limit, preserve the evidence and report the blocker rather than replacing the live system with a static-only substitute.

## Project structure
`frontend/` holds the existing React map/dashboard, an evaluation-summary view, Vite's same-origin dev proxy, and the static production build. `backend/` contains FastAPI read-only production routes, WebSocket streaming, and single-thread ownership of the SUMO environment. `simulation/` retains the uploaded `.sumocfg`, `.net.xml`, and `.rou.xml`. `rl_agent/` retains the Gymnasium/TraCI environment, reward, training/evaluation/inference scripts, trained PPO archive, an actor exporter, the low-memory NumPy actor, logs, and paired-seed evaluation data. Root `Dockerfile`, `plan.md`, `TODO.md`, `README.md`, and `app.config.ts` describe production packaging, operation, task outcomes, and platform project identity.

## Design direction
**Movement:** preserve the existing data-dense civic-operations-console / technical urban-observatory aesthetic rather than redesigning the supplied dashboard. **Core principles:** map-first visibility; evidence-led metric hierarchy; dense information with calm spacing; animation communicates live simulation only. **Color philosophy:** retain the current near-black navy background (`#04111d`) and cool blue/cyan map accents to suggest a precise night-time urban digital twin; reserve the existing mint green (`#20d67b`) for active/healthy state, amber for caution, and red for stopped or adverse conditions. The ownable signature color remains EcoTwin mint (`#20d67b`). **Layout paradigm:** asymmetric map-led operations dashboard with compact metric and signal-status rails; collapse into readable stacked sections on narrow screens instead of centering every panel in a uniform grid. **Signature elements:** small live-status lozenge; discrete signal-state lights in the map; restrained fine-line panel framing and telemetry traces.

**Interaction philosophy:** public users observe only; no interactive control affordances are shown or accepted by production API. Hover/focus may expose descriptive signal and metric details. **Animation:** existing vehicle motion and fresh telemetry transitions are preserved; keep effects subtle and brief, avoid decorative loops, and honor reduced-motion settings. **Typography:** preserve the current Inter-led system sans-serif stack (`Inter`, `ui-sans-serif`, platform system fallbacks) and existing metric hierarchy; retain tabular figures for comparative values and do not introduce an external font dependency during this deployment migration. **Brand essence:** “A live, learned-signal-control twin for observing city traffic and emissions”; personality is evidence-led, civic, and legible. **Brand voice:** concise, metric-led, neutral. Example lines: “PPO controller live — five signals adapting.” “Evaluation: mean wait improved; throughput remains a trade-off.” **Wordmark/logo:** reuse the supplied EcoTwin identity/icon asset; do not generate a replacement. **Signature brand color:** the existing EcoTwin mint green `#20d67b`.

## Public evaluation content
Present the measured five-seed paired comparison already in `rl_agent/evaluation/summary.json`, `baseline_vs_ppo.csv`, and `results.md`. Preserve the report's caveat that these are preliminary five-episode means: mean wait decreased 26.5%, queue decreased 34.4%, CO₂ decreased 2.0%, and throughput decreased 4.5%, with seed 105 a PPO regression. Do not overstate statistical certainty.
